E-REF  ·  Model Evaluation Report

A Convolutional Neural Network for Fresh–Rotten Food Classification

Architecture, training procedure, and a held-out evaluation reporting accuracy, precision, recall, and F1-score for the freshness-detection stage of the E-REF food-monitoring pipeline.

Model: YOLOv8n-cls (binary) Task: Fresh vs. Rotten Weights: eref_freshness_v2
Abstract

This report documents the design, training, and quantitative evaluation of the freshness-classification model used by the E-REF system to determine whether a food item is fresh or rotten from a single photograph. The model is a YOLOv8n-cls convolutional neural network trained as a binary classifier over images pooled from three independent photo collections spanning nine produce types and beef. On a held-out test set of 2,652 images the model achieves 99.51% accuracy, 99.48% macro-averaged precision, 99.52% macro-averaged recall, and a 99.50% macro-averaged F1-score. Recall on the rotten class—the safety-critical outcome, since a missed spoiled item is the costlier error—is 99.48%. A supplementary evaluation on a photograph collection entirely separate from training (fresh and rotten beef, not seen during model development) yields 99.39% accuracy, indicating the model generalises beyond its training distribution rather than memorising it.

1Introduction

Visual assessment of food freshness is a routine but error-prone task in household and food-service inventory management. The E-REF system automates this judgement as one stage of a three-stage computer vision pipeline: a detector locates the food in frame, an identification model determines which food it is, and a dedicated freshness model—the subject of this report—renders a binary fresh/rotten verdict from the same photograph. This document isolates that third stage and evaluates it on its own terms, independent of the identification and detection stages it is deployed alongside.

2Model Architecture

The freshness classifier is a YOLOv8n-cls network, the classification variant of the YOLOv8 architecture: a compact convolutional backbone (CSPDarknet-derived) followed by a global average-pooling classification head. The network is configured as a two-class softmax classifier over the labels fresh and rotten, and consumes the full camera frame at an input resolution of 224×224 px—no cropping or region proposal is applied upstream of this stage, since an earlier iteration of the pipeline found that feeding a detector's crop to the classification stage reduced accuracy rather than improving it.

In deployment, this model's output is fused with a second, food-aware freshness signal produced by E-REF's separate 19-class food-identification model (the share of its per-class probability mass resting on rotten_* labels). The fusion weights the dedicated freshness model at 0.65 and the identification model's signal at 0.35. All accuracy figures reported in this document describe the freshness model in isolation, prior to that fusion step.

3Dataset and Training Procedure

3.1 Data sources

Training examples were pooled from three photograph collections, to expose the model to more than one photographer, camera, and food category:

  • Primary produce dataset — nine food types (apple, banana, orange, tomato, potato, cucumber, capsicum, okra, bitter gourd), each labelled fresh or rotten.
  • Secondary produce collection — an independently sourced set of good/bad quality photographs covering a subset of the same food types, contributing additional fresh and rotten examples under different lighting and framing conditions.
  • Non-produce collection — fresh and rotten beef photographs, included so the freshness concept the model learns is not entirely tied to the colour and texture statistics of produce specifically.

Exact duplicate images (identified by content hash) were removed prior to splitting, and every image byte-identical to one already held out for evaluation in an earlier stage of this project was excluded from the training pool entirely, to prevent evaluation leakage.

4Evaluation Metrics

Four standard classification metrics are reported, computed from the confusion matrix over the held-out test set with rotten as the positive class:

Accuracy  =  (TP + TN) / (TP + TN + FP + FN)
Precision  =  TP / (TP + FP)
Recall    =  TP / (TP + FN)
F1-score  =  2 · (Precision · Recall) / (Precision + Recall)

Precision and recall are additionally macro-averaged (equal weight per class) and support-weighted (weighted by class size) across the two classes, following the same definitions used by scikit-learn's classification_report. No image in the test set was used during training or checkpoint selection.

The model's recall on the rotten class is 99.48%, meaning 8 of 1,531 rotten test images were missed. This is the single number most worth monitoring if the model is retrained or redeployed.

6Discussion and Limitations

  • Scope of the positive-result claim. The headline 99.5% accuracy describes performance on photographs drawn from the same underlying collections as training (even though the specific test images were unseen). It should be read as an upper bound on real-world performance, not a direct estimate of it.
  • Fusion in deployment. In the live E-REF pipeline this model's raw output is not used alone; it is combined with a second opinion from the food-identification model. The figures in this report isolate the freshness model's own accuracy, which is the more meaningful number for evaluating this component specifically, but will not be identical to the fused, end-to-end verdict the application ultimately shows a user.
  • Class balance. The training pool contains more rotten (13,532) than fresh (10,746) examples. Label smoothing and a cosine learning-rate schedule were used partly to counteract over-confidence this imbalance can otherwise induce; per-class recall in Table 3 shows no evidence of the model favouring the majority class.
  • Photographic conditions not yet covered. A related evaluation of this project's food-identification model found materially lower accuracy on plain white-background product photography than on naturalistic photos. The freshness model has not been separately stress-tested under that specific condition, and this is a reasonable target for future evaluation before the system is deployed against a photography style very different from its training data.

7Reproducibility

Every figure in this report is computed, not manually recorded. The dataset is assembled from source images by build_dataset.py; the model is trained by train.py; and all metrics in Sections 5.1–5.4 are produced by benchmark.py, which re-runs the trained model over each evaluation set and computes accuracy, precision, recall, and F1 directly from the resulting confusion matrix. Re-running the evaluation script against the committed model weights reproduces the numbers reported here.
